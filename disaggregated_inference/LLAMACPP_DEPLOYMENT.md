# llama.cpp Integration for Disaggregated Inference

## Overview

This guide explains how to integrate **llama.cpp** as the decode backend on Mac Studios, replacing Ollama or MLX, while keeping HuggingFace Transformers on DGX Sparks for prefill.

### Architecture

```
┌─────────────────┐           ┌──────────────────┐
│  DGX Spark 3    │           │  Mac Studio 2    │
│  (Prefill)      │──KV Cache→│  (llama.cpp      │
│  Transformers   │           │   Decode)        │
│  Qwen Model     │           │  Qwen GGUF       │
└─────────────────┘           └──────────────────┘
     169.254.150.105:8000          169.254.150.102:8001

┌─────────────────┐           ┌──────────────────┐
│  DGX Spark 4    │           │  Mac Studio 1    │
│  (Prefill)      │──KV Cache→│  (llama.cpp      │
│  Transformers   │           │   Decode)        │
│  GPT-OSS Model  │           │  Llama GGUF      │
└─────────────────┘           └──────────────────┘
     169.254.150.106:8000          169.254.150.101:8001
```

## Important Technical Note

### KV Cache Compatibility Challenge

**Current Limitation:** llama.cpp does **NOT** natively support external KV cache injection. This means:

- The KV cache generated by DGX (PyTorch/Transformers) cannot be directly injected into llama.cpp
- The formats are incompatible: PyTorch tensors vs llama.cpp's internal C++ structures
- llama.cpp manages its own KV cache internally

### Implementation Strategy

The current `decode_server_llamacpp.py` uses this approach:

1. **Receive prompt from DGX** (not the actual KV cache data)
2. **llama.cpp does its own prefill + decode** efficiently in one pass
3. **Return generated tokens** to orchestrator

This means:
- ✅ You get llama.cpp inference on Mac Studios
- ✅ GGUF model format for easy deployment
- ⚠️ The disaggregated architecture becomes **logical** rather than true KV cache sharing
- ⚠️ Mac Studios do both prefill and decode (llama.cpp is very efficient at this)

### Future Enhancement

To achieve true KV cache transfer, you would need to:

1. **Implement KV cache format conversion:**
   - PyTorch tensor → llama.cpp C++ format
   - Handle layer-by-layer conversion
   - Match attention head structures

2. **Modify llama.cpp source:**
   - Add API for external KV cache injection
   - Bypass internal prefill when KV cache provided
   - This requires C++ development and llama.cpp forking

3. **Or use a unified backend:**
   - Use llama.cpp on both DGX and Mac
   - Implement proper KV cache serialization/deserialization
   - Maintain KV cache compatibility

**For now, the practical solution is:**
- DGX prefill servers → coordination/routing
- Mac llama.cpp servers → efficient full generation (prefill + decode)

## Installation Steps

### Step 1: Install llama.cpp on All Machines


- Install `llama-cpp-python` with Metal support on Macs

## Performance Expectations

### llama.cpp on Mac Studio (Apple Silicon)

| Model | Size | Metal | CPU | Tokens/sec |
|-------|------|-------|-----|------------|
| Qwen-32B Q4_K_M | 18GB | ✅ | ✅ | 30-50 |

**Factors affecting speed:**
- Metal acceleration (GPU) vs CPU-only
- Model quantization level (Q4 faster than Q5/Q6)
- Context length (longer contexts = slower)
- Mac Studio specs (M1/M2 Max/Ultra)

## Troubleshooting

### Issue: "Model not loaded" or loading fails

**Check model file exists:**
```bash
ssh humphrjk@169.254.150.102 "ls -lh ~/models/gguf/*.gguf"
```

**Check available RAM:**
```bash
ssh humphrjk@169.254.150.102 "top -l 1 | grep PhysMem"
```

**Solution:** Use a smaller quantized model (Q4_K_M instead of Q5_K_M)

### Issue: "ModuleNotFoundError: No module named 'llama_cpp'"

**Reinstall llama-cpp-python:**
```bash
ssh humphrjk@169.254.150.102
CMAKE_ARGS="-DLLAMA_METAL=on" pip3 install --upgrade --force-reinstall llama-cpp-python --no-cache-dir
```

### Issue: Slow inference (<10 tok/s)

**Check if Metal acceleration is enabled:**
```bash
ssh humphrjk@169.254.150.102 "tail -100 ~/logs/decode_llamacpp.log | grep -i metal"
```

**Should see:**
```
Detected macOS - using Metal acceleration
GPU layers: 1
```

**If not using Metal, reinstall with Metal support.**

### Issue: Connection timeout

**Check server is running:**
```bash
ssh humphrjk@169.254.150.102 "ps aux | grep decode_server"
```

**Check port is listening:**
```bash
ssh humphrjk@169.254.150.102 "lsof -i :8001"
```

**Restart server:**
```bash
./start_mac_servers_llamacpp.sh
```

## Advanced Configuration

### Custom Context Window

Edit `start_mac_servers_llamacpp.sh`:
```bash
N_CTX=8192  # Increase from 4096 to 8192
```

Higher context = more memory usage but can handle longer prompts.

### GPU Layers Tuning

For optimal performance on Mac:
```bash
--n-gpu-layers 1   # Use Metal (recommended for Mac)
--n-gpu-layers 0   # CPU only
--n-gpu-layers -1  # Auto (may not work on Mac)
```

### Custom Model Path

Start server manually with custom model:
```bash
ssh humphrjk@169.254.150.102
cd ~/ai-homework-grader/disaggregated_inference
python3 decode_server_llamacpp.py \
    --model /path/to/your/model.gguf \
    --host 0.0.0.0 \
    --port 8001 \
    --n-ctx 4096
```

## Comparison: llama.cpp vs Ollama vs MLX

| Feature | llama.cpp | Ollama | MLX |
|---------|-----------|--------|-----|
| **Format** | GGUF | GGUF (internal) | safetensors/MLX |
| **Platform** | Cross-platform | Cross-platform | Mac only |
| **Metal (Mac)** | ✅ Yes | ✅ Yes | ✅ Yes (native) |
| **CUDA (DGX)** | ✅ Yes | ✅ Yes | ❌ No |
| **Model Management** | Manual | Automatic | Manual |
| **API Complexity** | Python bindings | REST API | Python API |
| **Quantization** | Q4/Q5/Q6/Q8 | Automatic | 4-bit/8-bit |
| **Speed (Mac)** | Fast | Fast | Fastest |
| **Flexibility** | High | Medium | High |

**Choose llama.cpp when:**
- You want GGUF model portability
- You need cross-platform compatibility
- You want direct Python API access

**Choose Ollama when:**
- You want easy model management
- You prefer REST API
- You want automatic updates

**Choose MLX when:**
- You're Mac-only
- You want maximum performance on Apple Silicon
- You prefer native Apple frameworks
